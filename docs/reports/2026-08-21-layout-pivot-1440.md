## 개요 (사용자 지시)

1. 태그라인 박스를 **왼쪽 끝에 밀착** 정렬 — 좌측 타이포와 HOME 버튼이 하나로 묶이는 구조
2. 사이트 전체 콘텐츠 **max-width 1440** (1920 아트보드 기준 좌우 마진 각 240)
3. **예외**: 홈 블라인드 UI는 1920 풀블리드 유지
4. HOME·WORK 콘텐츠 재배치

### WORK (`home.css`)

- 라벨: Work **left 240**(기존 right 1745), Menu **right 240** — 홈과 동일 좌표.
- 괘선: left **240**, 폭 **1440**. 하단 괘선 top 1007.6 → **891**.
- 세로 구분선: 높이 530.6 → **414**, 위치는 거터 중앙 **590 / 960 / 1330**
  (기존 피그마의 25%±15 오프셋은 새 그리드에서 의미가 없어 거터 중앙으로 정규화).
- 4단: 폭 425 → **330**, 거터 40 유지, left **240 / 610 / 980 / 1350** (우측 끝 1680).
- **단 전용 단위 `--cu` 도입** (`--cu: calc(var(--u) * 330 / 425)`): 단 내부 타이포·뱃지·마진은
  피그마 원 수치(24/41/148/30/40/22/70 등)를 그대로 두고 단위만 `--u`→`--cu`로 교체해
  모듈 전체를 비례 축소. 한글 타이틀 nowrap 이 기존과 같은 비율로 정확히 들어맞음.
- 썸네일: 고정 height 256u → **`aspect-ratio: 425/256`** (단 폭 330 기준 높이 자동 ≈198.8,
  원본 850×512 비율 유지, `saturate(0)` 표시·원본 무수정 원칙 그대로).

## 후속 수정 2 — 와이드 뷰포트 쏠림 · 태그라인 베이스라인 (사용자 스크린샷 피드백)

Orca 워커 분담 (같은 Run): Opus → `home.css`, Sonnet → `index.html`.

**① 워크 콘텐츠 좌측 쏠림 (근본 원인 수정)**
- 증상: 16:9보다 넓은 창에서 그리드·Work는 뷰포트 왼쪽에, Menu는 오른쪽에 붙어 어긋남.
- 원인: `--u`가 높이 기준일 때 아트보드 폭(1920u) < 뷰포트 폭인데, left 좌표(뷰포트 좌측 기준)와
  right 좌표(뷰포트 우측 기준)가 서로 다른 기준을 참조 — 아트보드가 좌우로 쪼개짐.
- 수정: 콘텐츠 레이어를 **폭 1920u 프레임으로 묶어 가로 중앙 고정**.
  홈 `.content` 를 `left:50% / width:1920u / translateX(-50%)` 프레임으로 변경,
  work 는 동일 원리의 `.work__frame` 래퍼(HTML+CSS) 신설. 블라인드는 풀블리드 예외 유지.
- 검증: 2400×1080 렌더에서 Work 왼끝~Menu 오른끝 사이에 그리드가 정확히 수납(원 디자인과
  동일한 관계), 홈도 중앙 정렬 확인. 1920×1080에서는 기존과 동일.

**② 태그라인–Menu 라인 헤이트 일치**
- Home 라벨 삭제 후에도 태그라인이 아래(top 204)에 남아 Menu와 다른 라인에 있었음.
- top 204 → **96**: 첫 줄 베이스라인(≈160)이 Menu 베이스라인(159)과 **같은 블라인드
  라인(162)** 위에 얹힘 — 피그마 19-269의 원 정렬 복원. 자간은 이미 메뉴와 동일(-.025em).
