## 후속 수정 — 메뉴 위치 통일 · 한글 폰트 (사용자 피드백)

- **메뉴 위치 통일**: work 화면의 Menu(및 짝을 이루는 Work 라벨)를 홈 `.menu__word` 와
  동일한 좌표·메트릭(top 102 / right 49 / 폰트 70 / 라인박스 83 / 자간 -.025em)으로 변경.
  앞으로 모든 화면의 메뉴 타이포는 이 좌표를 기준으로 한다. 렌더 대조로 홈과 정렬 확인.
- **한글 폰트 원인 조사**: CSS 는 이미 `--font-kr`(proxima-nova-hangeul 1순위)를 쓰고 있었음.
  Adobe Fonts 킷(rgb1grk)을 직접 조사한 결과 —
  1. **킷에는 proxima-nova-hangeul 700(Bold) 웨이트만 퍼블리시**되어 있음 (Medium 없음).
     500 을 요청해도 700 페이스로 렌더됨. 디자인이 Medium 이면 Adobe Fonts 에서 킷에
     Medium(500) 웨이트를 추가 + 재퍼블리시 필요.
  2. **킷은 허용 도메인에서만 로드** — `file://` 로 직접 열면 Typekit 이 거부되어
     맑은고딕 폴백으로 보임. `npx serve .` 로 열고 킷 도메인 설정에 localhost 포함 확인.
  코드 쪽은 폰트 스택·주석 정비 완료, 나머지 두 항목은 Adobe Fonts 계정에서만 해결 가능.
- **실측 검증 (localhost:8123 + 실브라우저)**: 킷 정상 로드 확인 — `document.fonts` 에
  proxima-nova-hangeul **400·700 두 페이스 loaded**, `wf-…-active` 클래스 부여, 한글 자형이
  맑은고딕과 명확히 구분됨. 즉 임베드 코드·CSS 는 정상. "폰트가 다르다"의 실체는
  ① `file://` 로 열면 킷 미로드 → 맑은고딕, ② 서버로 열어도 킷에 Medium(500)이 없어
  500 요청이 **400(Regular)** 페이스로 렌더 → 디자인(Medium)보다 가늘게 보임.
  해결: 반드시 로컬 서버로 열기 + Adobe Fonts 킷에 Medium 웨이트 추가·재퍼블리시
  (추가 즉시 기존 CSS `font-weight:500` 이 자동 반영됨).

## 후속 구현 — 썸네일 호버 인터랙션 (피그마 21-172)

- **에셋**: 사용자 제공 `assets/img/work_hover 1~4.png` (850×512, 베이스와 동일 크기 — 원본 무수정).
- **구조**: 각 카드의 `<img>` 를 `.project__thumbwrap`(overflow hidden, aspect-ratio 425/256)으로
  감싸고 그 안에 베이스(채도 0)와 호버(컬러) 이미지 2장을 겹침.
- **모션**: 카드 전체(`.project` — 타이틀~썸네일 프레임)에 커서를 올리면
  ① 컬러 이미지가 opacity 크로스페이드로 나타나고(.3s ease)
  ② 두 레이어가 함께 `scale(1.045)` 로 확대(.45s cubic-bezier(.23,1,.32,1), 확대분은 프레임 안에서 클리핑).
  opacity/transform 만 애니메이션(GPU 합성), `scale(0)`·filter 애니메이션 없음.
- **가드**: `@media (hover:hover) and (pointer:fine)` 로 터치 기기 탭 오호버 방지,
  기존 `prefers-reduced-motion` 전역 규칙이 트랜지션을 즉시 전환으로 축소.
- **검증**: 2단 카드에 호버 상태를 강제한 렌더 캡처로 컬러 전환·확대·클리핑·비호버 카드
  채도 0 유지 확인.
