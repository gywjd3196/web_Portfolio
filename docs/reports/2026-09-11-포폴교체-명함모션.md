# 2026-09-11 — 포트폴리오 PDF 교체 · 홈 명함 모션 추가

## 1. 개요

- **날짜** 2026-09-11
- **대상 파일** `assets/Portfolio/에이스카운터.pdf`, `assets/Portfolio/제로랩.pdf`, `index.html`, `assets/js/home.js`, `assets/css/home.css`
- **작업 차수** 1차 PDF 교체 · 2차 명함 살랑임/클릭 낙하 · 3차 낙하 시 블라인드 튕김 · 4차 워크·어바웃 메뉴 겹침 해결
- **진행 방식** 단일 세션 직접 작업. 변경 후 헤드리스 Chrome + CDP 로 모션·클릭 동작을 실제 측정해 검증.

## 2. 적용 완료된 변경

### 2-1. 포트폴리오 PDF 2건 교체

사용자가 원본 폴더(`OneDrive/web_Portfolio/assets/Portfolio`)에 새로 넣어 둔 파일로 교체했다. 파일명이 동일해 워크 카드·썸네일·레이아웃은 손대지 않았다.

| 파일 | 이전 | 이후 |
|---|---|---|
| 에이스카운터.pdf | 13,649,147 B | 8,718,662 B |
| 제로랩.pdf | 21,291,131 B | 22,986,196 B |

`index.html:105,138` — 브라우저가 옛 PDF 를 캐시에서 꺼내 쓰지 않도록 `?v=20260911` 을 붙였다. 제로랩은 원래 버전 파라미터가 없어 새로 추가. 페이지 수는 pdf.js 가 `doc.numPages` 로 읽으므로 하드코딩된 값이 없어 추가 수정 불필요.

### 2-2. 명함 — 정지 상태 살랑임 (클릭 유도)

`assets/js/home.js`

- `BOB_A = 7`, `BOB_T = 2200ms` 상수 추가. 진폭은 `unit()` 으로 비례 스케일(기준 1920×1080 에서 ±7px).
- `stepCard()` 에 `rest` 분기 신설 — 끼임 자리 기준 `y = BOB_A · unit · sin(2π(now − bobT0)/BOB_T)`.
- 스프링 복귀가 끝나 `rest` 로 들어가는 순간 `bobT0 = now` 로 위상을 리셋해, 복귀 직후 `y` 가 튀지 않고 0 에서 다시 시작한다.
- 렌더 게이트 `cardMoving` 을 `state !== 'rest'` → `state !== 'gone' && (BOB_A > 0 || state !== 'rest')` 로 변경. 정지 중에도 매 프레임 `--cy` 를 갱신해야 살랑임이 보이고, 명함이 떨어진 뒤(`gone`)에는 다시 멈춘다.
- `prefers-reduced-motion: reduce` 환경에서는 `BOB_A = 0` 이라 살랑임이 없고, 정지 시 스타일 기록도 하지 않는다(기존 동작과 동일).

명함은 `.card-mask` 의 clip-path 로 블라인드 4번째 경계선(216) 아래만 보이므로, 살랑임은 **슬롯에 끼인 명함이 조금씩 들락거리는** 모양으로 읽힌다. 위치 자체는 그대로 유지.

### 2-3. 명함 — 클릭 한 번으로도 낙하

기존에는 뷰포트 높이의 13%(`DROP_R`) 이상 끌어내려야 떨어지고, 그 미만이면 스프링으로 복귀했다. 여기에 "끌지 않고 그냥 눌렀다 뗀 경우"를 낙하로 추가했다.

- `card.dragged` / `card.downC` 필드 추가. `cardEl` pointerdown 에서 `dragged = false`, `downC = e.clientY` 로 초기화.
- pointermove 의 drag 분기에서 세로 이동이 8px 를 넘으면 `dragged = true`.
- `dropCard()` 조건을 `if (card.y < H * DROP_R)` → `if (card.dragged && card.y < H * DROP_R)` 로 변경. 즉 **끌어내린 경우에만** 임계값을 따지고, 클릭은 바로 `fall` 로 넘어간다.

낙하 모션 자체(중력 가속 → 종단 속도, sin 살랑임, rotateZ/rotateX)는 기존 코드를 그대로 재사용했다. 한 번 떨어진 명함이 다시 끼워지지 않는 동작(새로고침해야 리셋)도 유지.

### 2-4. 명함 낙하 시 블라인드 튕김 (인터랙션 힌트)

`assets/js/home.js`

명함을 클릭해 떨어뜨릴 때, 명함이 끼어 있던 경계(`CARD_ROW = 4`)에서 블라인드를 아래로 한 번 당겼다 놓는다. 슬랫이 벌어지며 안쪽 배경(숲 사진)이 잠깐 보였다가 출렁이며 닫힌다. **처음 방문한 사람에게 "커서로 블라인드를 움직일 수 있다"는 걸 알려 주는 신호**가 목적이다.

- 상수 `KICK_Y = 0.07`(뷰포트 높이의 7%만큼 아래로), `KICK_MS = 260`(당긴 상태 유지 시간) 추가.
- `kickBlind()` — `tear.index` 를 명함 경계로 놓고 `press.y` 를 그 아래로 밀어 `press.active = true` 로 만든다. **새 물리를 만들지 않고 기존 "꾹 눌러 당기기" 물리를 그대로 재생**하는 방식이라, 곡선 모양·전파 지연·감쇠 진동이 손으로 당길 때와 완전히 같다.
- 루프에서 `KICK_MS` 가 지나면 `press.active = false` — 이후는 기존 `REL_K/REL_D` 감쇠 스프링이 출렁이며 닫는다.
- 사용자가 직접 화면을 누르면(`stage` pointerdown) `kickT0 = 0` 으로 튕김 타이머를 취소해, 진행 중인 튕김이 사용자의 당김을 중간에 놓아 버리지 않게 했다.
- 끌어서 떨어뜨린 경우(`card.dragged`)에는 튕기지 않는다 — 그 경우 `CARD_GAIN` 으로 블라인드가 이미 따라 내려와 있어 두 번 움직이면 어색하다.
- `prefers-reduced-motion` 에서는 `KICK_MS * MOTION` = 13ms 로 사실상 즉시 끝난다.

### 2-5. 워크·어바웃 메뉴와 페이지 글자 겹침 해결

`assets/css/home.css:191-198`

메뉴를 내리면 Menu~Linkedin 글자가 아래 콘텐츠(카드 제목·날짜·괘선)와 겹쳐 읽히지 않던 문제. 메뉴 글자 뒤에 흰 바탕을 깔아 해결했다.

```css
#workMenu .menu__word,
#aboutMenu .menu__word{background:var(--paper);}
```

- 바탕을 `.menu__slot` 이 아니라 **`.menu__word` 에 건다.** 슬롯은 `overflow:hidden` 이고 글자가 `translateY(-100%)` 로 숨어 있다가 내려오는 구조라, 글자에 바탕을 붙이면 바탕이 글자와 **같이 슬라이드**한다. 여닫는 0.24초 동안 바탕이 먼저 나타나거나 늦게 사라지는 일이 없고, 닫힌 상태에서는 슬롯 밖으로 숨어 흰 기둥이 보이지 않는다. 타이밍 보정 코드가 전혀 필요 없다.
- 흰 바탕의 폭은 `.menu` 프레임 폭(195u, 피그마 텍스트 프레임)과 같고 높이는 라인박스 83u — 요청대로 **글자 영역 프레임만** 덮는다.
- 홈 `#menu` 는 제외했다. 블라인드 위에 얹혀 있어 겹침 문제가 없고, 흰 박스를 깔면 블라인드 당김 연출을 가린다.
