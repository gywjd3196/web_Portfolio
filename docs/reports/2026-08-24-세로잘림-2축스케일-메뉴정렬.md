# 세로 잘림 해결(2축 스케일) + 홈 메뉴/FAB work 정렬 + 메뉴 호버 유지

## 개요

- **날짜**: 2026-08-24
- **대상 파일**: `assets/css/home.css` (단독 수정 — `home.js`·`index.html` 무수정)
- **진행 방식**: Orca 워커(레이아웃2) 단독 구현. `home.js` 는 다른 워커 소유라 CSS 만으로 해결.

## 적용 완료된 변경

### 1. 2축 스케일 도입 (`:root`)

- `--u`: `min(100vw/1920, 100vh/1080)` → `calc(100vw/1920)` 전역 변경 (가로 단위)
- `--uy: calc(100vh/1080)` 신설 (세로 단위)
- 오버레이(`.work/.about/.detail`) 범위의 `--u`·`--cu` 재정의 제거 (전역화로 불필요)
- 오버레이 y축 좌표 전부 `--uy` 전환:
  - work: 라벨/메뉴 top 129, 괘선 414/1008.6, 세로선 445.9/530.6, 카드 top 448
  - 카드 내부 세로 간격: 타이틀 mb 148/103, 클라이언트 mb 24, meta mb 19
  - 썸네일: `aspect-ratio:425/256` → `height:calc(256*var(--uy))` (img 는 기존 `object-fit:cover` 로 크롭)
  - detail: 바 h132, 화살표/타이틀/닫기 top 41/41.8, pdfarea top 132/h 948/min-height, pdf top 41.5/height/gap 20, 세로선, 괘선 414/1008.6, 카드 top 446
- **`--u` 유지 (예외)**: font-size, line-height, letter-spacing, `.menu__slot` 높이 83(overflow:hidden 잘림 방지), 뱃지·가로 간격, 홈 태그라인 위치
- 결과: 16:9 에서 픽셀값 변경 전과 동일, 세로가 짧은 화면에선 세로만 비례 압축 → 스크롤 없이 전체 표시. `overflow-y:auto` 는 안전망으로 유지.

### 2. 홈 메뉴·FAB 위치를 work 와 통일

- `.menu`: top 102→`129*--uy`, right 240→`47*--u` (오버레이 쪽 중복 오버라이드 `.work .menu,.about .menu` 삭제 — 홈·오버레이 단일 규칙)
- `.fab`: right 240→`47*--u`, bottom 71 은 `--uy` 로
- 홈 태그라인 위치는 무수정

### 3. work 메뉴 호버 유지 버그

- `.menu` 에 `z-index:20` 부여 — 열린 메뉴 하단 슬롯(About/Email/Linkedin)이 괘선(414)·카드(448~) 위에 오게 되어 pointerleave 반복 닫힘 해소. CSS 만으로 해결(JS 무수정).
- 검증: `.detail` 안에는 메뉴가 없어(index.html 확인) is-zoom 시 `pdfarea z-index:5` 와 충돌 없음.

### 4. 홈 폰트 = work 폰트

- 1번의 전역 `--u` 변경으로 태그라인(100)·메뉴(70)가 work 와 같은 vw 기준 — 숫자 무변경. `min()` 잔재 grep 으로 0건 확인.

## 검수/검산

| 항목 | 결과 |
|---|---|
| 1920×1080 (u=uy=1) | 변경 전후 오버레이 픽셀값 동일 |
| 1920×858 (uy≈0.794) | 하단 괘선 1008.6×0.794≈801 < 858 → 잘림 없음 |
| min() 잔재 | grep 0건 |
| .detail 내 메뉴 z-index 충돌 | 해당 없음 (detail 에 메뉴 미존재) |

미적용/알려진 한계: 카드 내부에서 line-height(글리프)는 `--u`, 마진은 `--uy` 라 극단적으로 짧은 화면에선 카드 스택이 괘선보다 몇 px 어긋날 수 있음 — `overflow-y:auto` 안전망으로 커버.
