# PDF 상세 뷰어 로딩 체감 개선

## 개요

- **날짜**: 2026-08-24
- **대상 파일**: `assets/js/home.js`(PDF 섹션), `tools/serve.js` — 소유권 규칙에 따라 이 두 파일만 수정. `home.css`·`index.html` 은 건드리지 않음
- **진행 방식**: Orca 워커 단독 작업 (task_7a24ab0708f5). 코드 수정 → `node --check` 구문 검증 → 로컬 서버 기동 후 curl 로 Range 응답 4종 실측 검증

## 적용 완료된 변경

### assets/js/home.js

1. **문서 캐시** — `pdfCache`(Map, url→getDocument 태스크) 도입. `clearPdf()` 에서 `pdfTask.destroy()` 제거, DOM/IntersectionObserver 만 정리. 같은 카드 재열기 시 파싱 0초. `index.html` 쪽 `?v=` 캐시버스터가 붙어도 url 이 키라 자동으로 새 항목이 된다. 로드 실패 시엔 캐시에서 지워 재시도 가능.
2. **프리로드** — `openWork(true)` 시 4개 PDF 를 백그라운드 순차 파싱(`preloadPdfs`, 1회만). 카드 `pointerenter` 시 해당 PDF 를 즉시 시작(캐시가 중복 시작 차단). `file://` 에선 모두 건너뜀.
3. **스트리밍 첫 페이지 우선** — `getDocument` 에 `disableAutoFetch:true, rangeChunkSize:1MB` 옵션. 전체 다운로드 없이 필요한 조각만 받아 첫 페이지를 그린다. `file://` 안내 분기는 유지.
4. **로딩 표시** — 파싱 대기 중 `.detail__notice` 로 "불러오는 중…" 표시(기존 클래스 재사용, CSS 수정 없음). 첫 캔버스 렌더 완료 시 제거, 로드 실패 시 실패 문구로 교체.
5. **첫 2페이지 즉시 렌더** — IntersectionObserver 를 기다리지 않고 캔버스 생성 직후 렌더 시작. 3페이지부터 기존 IO(lazy) 방식.
6. **렌더 해상도 축소** — 기본 렌더 폭을 `innerWidth × DPR` → `innerWidth × 1303/1920 × DPR`(실제 표시 폭)로 낮춤(픽셀 수 약 54% 감소). 확대(is-zoom) 시 이미 그려진 캔버스만 전체 폭으로 재렌더(`pdfRerender`), 이후 렌더되는 페이지도 확대 상태를 반영. `canvas.dataset.w` 로 동일/상위 해상도 중복 렌더 방지.

### tools/serve.js

7. **HTTP Range(206) 지원** — 기존엔 미지원(항상 200 전체 응답). `fs.stat` + `createReadStream(start,end)` 로 단일 범위 206, 꼬리 범위(`bytes=-N`), 416(Range Not Satisfiable), 그리고 모든 200 응답에 `Accept-Ranges: bytes` + `Content-Length` 추가(pdf.js 가 range 전환을 판단하는 데 필요). `readFile` 전체 버퍼링도 스트림으로 교체.

### ponytail: 의도적 상한 (주석으로 명시)

- `pdfCache` 무제한 — PDF 4개뿐. 수십 개로 늘면 LRU 로 교체 (`home.js`)
- 확대 후 축소해도 고해상도 캔버스 유지(메모리 ↑) — 문제 되면 축소 시 다운렌더 추가 (`home.js`)
- Range 는 단일 범위만 — 다중 범위(`bytes=a-b,c-d`)는 200 전체 응답 폴백 (`serve.js`)

| 심각도 | 항목 | 결과 |
|---|---|---|
| — | `node --check` home.js / serve.js | 통과 |
| — | `Range: bytes=0-99` → 206 + 올바른 Content-Range/Length | 통과 (실측) |
| — | 일반 요청 → 200 + `Accept-Ranges: bytes` + Content-Length | 통과 (실측) |
